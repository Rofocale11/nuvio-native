## Other design records

Files not listed above are design records, plans and dated audits. Some still describe behaviour
in the tree — `disk-budget.md`, `remote-keys.md`, `launch-links.md`, `two-installs.md`,
`playback-settings.md`, `settings-form.md`, `player-submenus.md`, `search.md`,
`lab-diagnostics.md`, `webos10-lab-report.md` — and others are upstream history
(`*-plan.md`, `*-design.md`, `architecture-review-*`, `simplification-audit-*`, `kodi-parity-*`,
`v0.7-*`, …). Read them for the reasoning and check the code before relying on them. If a design
record becomes current again, move its content into the owning document above and link it here.

Assets and raw records live in `assets/`, `design-briefs/`, `measurements/` and `screenshots/`.

## Rules for these documents

- The owning document for an area is the table in [`../AGENTS.md`](../AGENTS.md) §Documentation.
- A behaviour change updates its owning document in the same commit.
- An upstream page must carry the "Upstream reference — not this product" banner or be listed in
  the upstream table above.
- Derived numbers are generated by `tools/ai-docs-refresh.sh`; never edit a marked value.
